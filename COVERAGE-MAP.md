## web — nav.test.ts FIXED (2026-09-04)

All 69 tests pass. `nav.ts` is at **99.6% statement / 92.7% branch / 90% function** coverage.

Root cause of the 12 original failures: the tests used legacy 6-role names
(`MANAGER`, `SALES`) from `UserCompany.role`, but `nav.ts` uses the 14-role
system from `roles.ts` (`PROJECT_MANAGER`, `SALES_MANAGER`). The role string
flowing from `/api/me` → `app-shell.tsx` → `worldsFor()` uses the new system.

Fixes applied:
1. **`nav.ts`**: Added `normalizeNavRole()` using `migrateRole()` from `roles.ts`
   — maps legacy roles (MANAGER→PROJECT_MANAGER, SALES→SALES_MANAGER) and
   falls back to SUPERVISOR for unknown strings. Applied in `worldsFor`,
   `linksFor`, `settingsLinksFor`, `homeWorldFor`. This is a defensive measure
   so nav.ts degrades gracefully if a legacy role ever reaches it.
2. **`nav.test.ts`**: Updated role constants to use canonical new-system names.
   Fixed outdated expectations: SETTINGS_LINKS grew from 3 to 6 links;
   PROJECT_MANAGER lands in Build (not Today); SALES_MANAGER sees Procure
   (Quotations explicitly grants SALES_MANAGER access).
