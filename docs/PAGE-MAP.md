## How to read this map

Every page is grouped by its **business context** (the "what"). Within each group, I show:
- **Pages** — the route + what it does
- **Roles** — who can see/use it
- **GL/Accounts** — what journal entries it triggers (the financial truth)
- **Workflow** — what comes before it, what comes after it
- **Logic connectivity** — which service functions fire, what data flows in/out, what other pages it touches

## GROUP 1: IDENTITY & COMMAND CENTER
*Context: Who you are, what needs your attention, what you approve*

| Page | Route | Roles |
|------|-------|-------|
| Profile | `/` | ALL 6 |
| My Tasks | `/my-tasks` | ALL 6 |
| Approvals | `/approvals` | OWNER, ADMIN, MANAGER |

**GL/Accounts:** None directly — but approvals *unlock* the GL-posting mutations downstream.

**Workflow connectivity:**
```
Profile → sees queues (pending approvals, assigned tasks)
  ├─ Approvals → approves PO/Requisition → unlocks procurement
  └─ My Tasks → completes task steps → may trigger stock issue, DPR, etc.
```

**Logic connections:**
- Profile pulls from: `AuditLog`, `UserCompany`, `RolePermission`, task counts, approval counts
- Approvals page feeds into: `procurement.approvePO()`, `requisition.approve()` — both call `logAction()` + `postJournalEntry()` downstream
- My Tasks connects to: `task.ts` service (subtasks, dependencies, time tracking)

## GROUP 2: PROCUREMENT LIFECYCLE
*Context: "I need material" → quotes → PO → receive → pay*

| Page | Route | Roles |
|------|-------|-------|
| Material Indents (Requisitions) | `/requisitions` | OPS + ACCOUNTANT |
| Purchase Orders | `/procurement` | OPS + ACCOUNTANT |
| Suppliers (Vendors) | `/vendors` | OPS + ACCOUNTANT |
| Rate Contracts | `/rate-contracts` | BOOKS |
| GRN / Receive | `/field` | OPS |
| Purchase Returns | `/supplier-returns` | OPS + ACCOUNTANT |
| Direct Purchases | (API only, print at `/print/direct-purchase/[id]`) | OPS + ACCOUNTANT |

**GL/Accounts:**
| Action | GL Entry |
|--------|----------|
| Receive goods (GRN) | `postPurchaseReceipt()` → Dr Inventory / Cr GRN Clearing, Dr ITC (GST input) |
| Purchase return | `postSupplierReturn()` → reverses receipt, Cr Inventory / Dr Supplier |
| Direct purchase | Same as GRN but bypasses PO |

**Workflow connectivity:**
```
Requisition (DRAFT → SUBMITTED)
  ↓ [requires requisition.approve]
Requisition (APPROVED)
  ↓ [quote gate: ≥3 quotes uploaded, or waived]
  ↓ ComparativeQuotePanel → select winning quote
Purchase Order (DRAFT → APPROVED → ORDERED)
  ↓
GRN / Receive (PARTIAL → RECEIVED)
  ↓ [stock increments, MAC recalculated]
  ↓ [GL: postPurchaseReceipt]
Stock available at location
  ↓
Purchase Returns (if defective)
  ↓ [stock decrements, GL reversal]
```

**Logic connections:**
- `generateAutoRequisition()` — fires when stock ≤ reorderPoint, creates DRAFT requisition automatically. Connects **Stock** → **Requisitions**
- `quote-comparison.ts` — `isQuoteGateSatisfied()` blocks PO conversion until 3 quotes uploaded. Connects **Requisitions** → **Quotes** (embedded in convert dialog) → **Purchase Orders**
- `getWinningQuoteLineCosts()` — auto-fills PO line costs from selected quote. Connects **Quotes** → **PO**
- `recordMovement()` (RECEIPT type) — fires on GRN, updates `StockLocationItem.qty` + `movingAvgCost`. Connects **GRN** → **Stock**
- `computeMovingAverageCost()` — recalculates MAC on every receipt. Connects **GRN** → **Stock** → **Inventory Value report**
- Rate Contracts → feeds into PO line pricing (pre-negotiated rates)
- Supplier ratings → fed from PO delivery performance. Connects **PO** → **Suppliers** (ratings tab)

**Reports fed by this group:**
- `/reports/purchase-register` — every purchase bill
- `/reports/purchase-trends` — buying patterns, rate movements
- `/reports/purchaser-performance` — quote collection efficiency per buyer
- `/reports/pending-payments` — supplier payables

## GROUP 3: STOCK & MATERIAL CONTROL
*Context: "What do I have, where, and what's it worth?"*

| Page | Route | Roles |
|------|-------|-------|
| Stock (hub) | `/stock` | OPS + ACCOUNTANT |
| ↳ On-hand tab | | |
| ↳ Movements tab | `/stock-movements` → redirect | |
| ↳ Transfers tab | | |
| ↳ Issues tab | | |
| ↳ Scrap tab | `/scrap-generations` → redirect | |
| ↳ Counts tab | `/stock-counts` → redirect | |
| Material Catalogue | `/materials` | OPS |
| Consumption Benchmarks | `/standard-consumptions` | OPS + ACCOUNTANT |
| Material Reconciliation | `/material-reconciliation` | OPS |
| Equipment | `/equipment` | OPS |

**GL/Accounts:**
| Action | GL Entry |
|--------|----------|
| Issue material to project/unit | `postMaterialIssue()` → Dr WIP / Cr Inventory |
| Scrap generation | `SCRAP_GENERATED` movement (IN) — no GL (internal reclassification) |
| Scrap sale (linked to project) | `postAssetSale()` + credits `ACCT.COST_RECOVERY` |
| Stock count adjustment | Reconcile variance → Dr/Cr Inventory / Dr/Cr Stock Adjustment |
| Equipment assignment | No GL (asset tracking only) |

**Workflow connectivity:**
```
Stock On-Hand (current qty per location)
  ↓
Transfers (location → location, MAC carries over)
  ↓
Issues (location → project or specific built unit)
  ↓ [GL: postMaterialIssue → WIP]
  ↓ [if builtUnitId set: cost goes directly to that unit]
  ↓ [if projectId only: cost pooled, area-allocated later]
Project/Unit cost increases
  ↓
Scrap Generation (over-consumption detected from DPR)
  ↓ [SCRAP_GENERATED movement, stock IN at scrap value]
Scrap available for sale → Material Sales
  ↓
Stock Counts (physical verification)
  ↓ [reconcile: adjust qty, log variance]
```

**Logic connections:**
- `recordMovement()` / `recordTransfer()` — the ONLY way stock changes. Every page in this group calls these. Connects **all stock pages** → **StockLocationItem** + **StockMovement** (immutable audit)
- `reallocateProjectCosts()` — recalculates `costPerSqft` + `unit.productionCost` after issues change. Connects **Stock Issues** → **Projects** → **Built Units** → **Profit Center**
- `runDprVarianceAnalysis()` — compares DPR material lines vs `StandardConsumption`, auto-flags scrap. Connects **DPR** → **Consumption Benchmarks** → **Scrap Generation** → **Stock**
- `reconciliation.ts` — required vs issued vs consumed vs stock. Connects **BOQ** → **Issues** → **DPR** → **Stock**
- Equipment → assignments/returns/maintenance — connects to **Tasks** (maintenance tasks) and **HR** (who has the equipment)

**Reports fed by this group:**
- `/reports/inventory-value` — stock valuation by location (MAC-based)
- `/reports/stock-movement-summary` — opening/received/issued/closing
- `/reports/issue-register` — every issue slip
- `/reports/department-consumption` — cost centre usage

## GROUP 4: REAL ESTATE ASSET LIFECYCLE
*Context: "Land → Projects → Units → Sell/Rent"*

| Page | Route | Roles |
|------|-------|-------|
| Land Parcels | `/land` (+ `/land/[id]`) | SELLING |
| Projects | `/projects` (+ `/projects/[id]`) | ALL 6 |
| BOQ | `/boq` | BOOKS |
| Schedule (WBS) | `/wbs` | BOOKS |
| Measurement Book | `/measurement-book` | OPS |
| Work Orders | `/work-orders` | BOOKS |
| Built Units | `/units` | SELLING |
| Renovations | `/renovations` → redirect to `/projects` | ALL 6 |

**GL/Accounts:**
| Action | GL Entry |
|--------|----------|
| Land purchase | `postLandPurchase()` → Dr Land Bank / Cr Cash/Supplier |
| Land partition | No GL (internal reclassification: parent → children) |
| Project cost added | `postProjectCost()` → Dr WIP / Cr Cash/Expense |
| Material issued to project | `postMaterialIssue()` → Dr WIP / Cr Inventory |
| Work order RA bill | `postProjectCost()` → Dr WIP / Cr Subcontractor Payable |
| Built unit valuation | No GL (updates `productionCost` field only) |

**Workflow connectivity:**
```
Land Purchase (acquire whole plot)
  ↓ [GL: postLandPurchase]
Land Parcel (WHOLE status)
  ↓ [partition: Σ child area = parent area]
Land Parcels (PARTITIONED children)
  ↓
Project (created on a parcel)
  ↓
BOQ (budget — what we plan to spend, line by line)
  ↓
WBS (schedule — when, in what order, dependencies)
  ↓
Construction begins:
  ├─ Material Issues → project/unit cost ↑
  ├─ Work Orders (subcontractor) → RA bills → project cost ↑
  ├─ Measurement Book → verified quantities executed
  └─ DPR → progress + variance analysis
  ↓ [reallocateProjectCosts: costPerSqft = totalCost / sellableArea]
Built Units (flats, shops, plots)
  ↓ [unit.productionCost = costPerSqft × area + direct issues]
  ↓
Status: AVAILABLE → BOOKED → SOLD / RENTED
```

**Logic connections:**
- Land partition is atomic: validate area sum, create children, set parent PARTITIONED, record `LandPartition`. Connects **Land** → **Land** (parent-child)
- `reallocateProjectCosts()` — the bridge between **Stock Issues** and **Built Unit valuation**. Separates project-level costs (area-allocated pool) from unit-direct costs (specific unit). Connects **Stock** → **Projects** → **Units**
- BOQ → Budget Variance report: connects **BOQ** → actual costs from issues + work orders + project costs
- WBS → scheduling, dependencies, critical path. Connects to **Tasks** (WBS nodes become tasks)
- Measurement Book → connects to **Work Orders** (RA bills reference MB entries) and **DPR** (quantities verified)
- Work Orders → TDS + retention accounting. Connects to **Finance** (payments) and **GL** (project cost posting)
- Renovation projects → same lifecycle, just `projectType = RENOVATION`. Filtered on `/projects`

**Reports fed by this group:**
- `/reports/project-progress` — planned vs actual per site
- `/profit-center` — per-project P&L, margin, cost/sqft
- `/budget-variance` — BOQ vs actual, overrun flags
- `/project-control` — EVM (CPI/SPI), forecast, commitments, MTO

**GL/Accounts:**
| Action | GL Entry |
|--------|----------|
| Unit sale (booking) | `postPaymentReceived()` → Dr Cash/Bank / Cr Sales Revenue + Cr Output GST |
| Sale payment received | `postPaymentReceived()` → Dr Cash/Bank / Cr Customer Receivable |
| Material sale | `postAssetSale()` → Dr Cash/Receivable / Cr Inventory + Cr Output GST |
| Scrap sale (project-linked) | `postAssetSale()` + Cr `ACCT.COST_RECOVERY` (reduces project cost) |
| Rental payment | `postPaymentReceived()` → Dr Cash / Cr Rental Income |

**Workflow connectivity:**
```
Built Unit (AVAILABLE)
  ↓
Portal Listings → sync to 99acres/MagicBricks/Housing.com
  ↓
Customer enquiry → Booking (SALE status)
  ↓ [GL: postPaymentReceived]
Payment Plan → installments → collections
  ↓
Unit SOLD → delist from portals automatically
  ↓
OR: Unit RENTED → Rentals page → monthly rent collection
  ↓
Material Sales (surplus/scrap)
  ↓ [if scrap + projectId: cost recovery reduces project cost]
  ↓ [GL: postAssetSale + COST_RECOVERY credit]
```

**Logic connections:**
- `createMaterialSale()` — when linked to `projectId`, `scrapSubtotal` subtracts from `projectTotalCost()` and `reallocateProjectCosts()`. Connects **Material Sales** → **Projects** → **Built Units** (reduces production cost)
- `syncListingToPortal()` / `delistPortalListing()` — when unit status changes to SOLD, portal listing auto-delists. Connects **Sales** → **Portal Listings**
- `tenancy.ts` — rental agreements, rent schedules, payment tracking. Connects **Rentals** → **Finance** (rent income) → **GL**
- CRM (`crm.ts`) — customer lifecycle. Connects **Sales** → **Customers**

**Reports fed by this group:**
- `/reports/sales-revenue` — what sold, at what price, trend
- `/reports/profit` — revenue minus cost, per project and overall
- `/reports/pending-payments` — customer receivables, overdue

## GROUP 6: HR, LABOUR & PAYROLL
*Context: "Who works, how long, what did they do, what do they cost"*

| Page | Route | Roles |
|------|-------|-------|
| People Today (HR overview) | `/hr` | OPS + ACCOUNTANT |
| Employees | `/hr/employees` | OPS + ACCOUNTANT |
| ↳ Crews/Gangs tab | | |
| Attendance | `/hr/attendance` | OPS + ACCOUNTANT |
| ↳ Leave tab | | |
| Daily Progress (DPR) | `/hr/dprs` | OPS |
| Payroll | `/hr/payroll` | BOOKS |

**GL/Accounts:**
| Action | GL Entry |
|--------|----------|
| Payroll run | `postExpense()` → Dr Labour Expense / Cr Cash/Bank + Cr Statutory Dues |
| DPR with material variance | Triggers scrap detection → `SCRAP_GENERATED` movement (no GL until scrap sold) |

**Workflow connectivity:**
```
Employees (roster, wage rate, posting)
  ↓
Crews/Gangs (group workers, assign to site)
  ↓
Attendance (daily: present/half-day/absent + GPS check-in)
  ↓ [GPS-tagged, calculates effective work hours]
  ↓
DPR (what work got done, by whom, material used)
  ↓ [if workType set: runDprVarianceAnalysis]
  ↓ [compares actual material vs StandardConsumption]
  ↓ [over-consumption → auto-scrap generation]
  ↓
Payroll (attendance × wage rate = salary)
  ↓ [GL: postExpense → Labour Expense]
  ↓ [labour cost feeds into project cost via reallocateProjectCosts]
```

**Logic connections:**
- `recordAttendance()` / `bulkRecordAttendance()` — GPS coordinates attached. Connects **Attendance** → **Payroll** (hours → salary calculation)
- `runDprVarianceAnalysis()` — the critical bridge: compares DPR material lines vs `StandardConsumption` benchmarks. Over-consumption → auto-generates `ScrapGeneration` with `SCRAP_GENERATED` stock movements at 50% standard cost. Connects **DPR** → **Consumption Benchmarks** → **Scrap** → **Stock**
- DPR multi-tier approval: SUBMITTED → SUB_ADMIN_APPROVED (MANAGER) → APPROVED (OWNER/ADMIN). Connects **DPR** → **Approvals**
- Payroll → `postExpense()` → GL. Labour cost flows to project via `reallocateProjectCosts()`. Connects **Payroll** → **GL** → **Projects** → **Profit Center**
- Leave management → `leave.ts`. Connects **Attendance** → leave balances → payroll deductions

**Reports fed by this group:**
- `/reports/payroll-expense` — labour cost per site per month
- `/reports/project-progress` — DPR-driven progress %

## GROUP 7: FINANCIALS, BOOKS & TAX
*Context: "The financial truth — double-entry books that balance"*

| Page | Route | Roles |
|------|-------|-------|
| Finance | `/finance` | BOOKS |
| General Ledger | `/gl` | BOOKS |
| ↳ Tally Sync panel | | |
| GST | `/reports/gst` | BOOKS |
| All Insights (report picker) | `/reports` | REPORTS |

**GL/Accounts:** This group IS the GL. It receives postings from every other group.

**Workflow connectivity — where every GL entry comes from:**
```
PROCUREMENT:    GRN → postPurchaseReceipt()     → Dr Inventory/Cr GRN Clearing/Dr ITC
                Return → postSupplierReturn()    → reversal
STOCK:          Issue → postMaterialIssue()      → Dr WIP/Cr Inventory
                Scrap sale → postAssetSale()     → Dr Cash/Cr Inventory/Cr COST_RECOVERY
REAL ESTATE:    Land → postLandPurchase()        → Dr Land/Cr Cash
                Project cost → postProjectCost() → Dr WIP/Cr Cash
                Work order → postProjectCost()   → Dr WIP/Cr Subcontractor Payable
SALES:          Sale → postPaymentReceived()     → Dr Cash/Cr Revenue/Cr Output GST
                Rental → postPaymentReceived()   → Dr Cash/Cr Rental Income
HR:             Payroll → postExpense()          → Dr Labour Expense/Cr Cash
FINANCE:        Expense → postExpense()          → Dr Expense/Cr Cash
                Payment → postPaymentReceived()  → Dr (varies)/Cr Cash
```

**Logic connections:**
- `postJournalEntry()` — every domain helper calls this inside the same transaction as the source mutation. Books never diverge from reality. Connects **ALL groups** → **GL**
- 18 system accounts (`GlAccount`), seeded via `seedChartOfAccounts()`. Account codes in `ACCT` const
- `trialBalance()` + `accountLedger()` — reporting. Connects **GL** → **All Insights**
- Tally sync: `generateTallyVoucherXml()` + `syncBatchToTally()` — pushes `JournalEntry` → Tally XML. `TallySyncLog` tracks status. Connects **GL** → **Tally** (external)
- GST: ITC debited on purchases (input), Output GST credited on sales. Connects **Procurement** + **Sales** → **GST report**

**Reports fed by this group:**
- `/reports/profit` — P&L from GL
- `/reports/comparative` — period-over-period from GL
- `/reports/gst` — ITC + output GST
- `/reports/pending-payments` — receivables/payables from GL
- `/reports/expenses` — expense breakdown from GL

**GL/Accounts:** Indirect — reads WIP, project costs, revenue from GL.

**Workflow connectivity:**
```
BOQ (planned budget)
  ↓
WBS (planned schedule)
  ↓
Actuals flow in from:
  ├─ Material Issues (Stock group)
  ├─ Work Orders (RA bills)
  ├─ Project Costs (Finance)
```

- EVM → `finance-advanced.ts` — CPI/SPI from actual cost (GL) vs earned value (DPR progress × BOQ budget)
- Material Take-Off → `material-take-off` API — what materials are needed, derived from BOQ
- `reconciliation.ts` — required (BOQ) vs issued (Stock) vs consumed (DPR) vs stock (StockLocationItem). The four-way reconciliation
