## 2. Discussion Summary

The meeting outlines the development of a custom Enterprise Resource Planning (ERP) software tailored for a real estate and construction business. The client requires a unified system to manage raw material supply chains (centralized and decentralized), real estate asset tracking (plots vs. units), HR functions (payroll and DPR), and financial syncing with Tally. A major focus is placed on cost control through "Comparative Analysis" of vendor quotes and data visualization via a mobile-responsive dashboard.

## 3. Project Requirements

- **Inventory:**
  - Raw Material tracking (Purchase, Sale, Scrap generation).
  - Centralized Store vs. Individual Company procurement.
  - Real Estate tracking (Whole plots, Sub-divided units, Flats).
- **HR & Payroll:**
  - Attendance tracking with specific rules (Late, Half-day).
  - Daily Performance Reports (DPR) for site and office staff.
  - Purchaser Performance: Quota comparison system.
- **Financials / Integration:**
  - Two-way Tally API integration.
  - Real estate portal integration (99acres) for automated listings.
- **System Admin:**
  - Multi-level hierarchy (Admin > Sub-Admin > Sub-Sub-Admin).
  - Role-based access control (RBAC).

## 4. Software Requirements Specification (SRS)

### Introduction

The "Business Management Suite" is a cross-platform application designed to streamline construction inventory, real estate sales, and employee performance.

### Functional Requirements

1. **Inventory Module:** Support for "Stock-in" (Purchase) and "Stock-out" (Sales/Construction use). Ability to "Create" items (Scrap).
2. **Real Estate Module:** Asset lifecycle management from "Plot Purchase" to "Unit Creation" to "Sold" status.
3. **Comparative Quote Engine:** A mandatory workflow for purchasers to upload 3 PDFs/Images of quotes before approval.
4. **DPR System:** Mobile interface for site supervisors to input labor and material usage daily.

### Non-Functional Requirements

1. **Usability:** Mobile-first design for field staff; Data-heavy dashboard for Admin.
2. **Reliability:** Real-time sync between Mobile and Desktop.
3. **Security:** Encrypted Tally API keys and hierarchical data siloed by user level.

## 5. System Architecture & Database Design

### Tech Stack (Suggested)

- **Frontend:** React.js (Desktop), React Native (Mobile).
- **Backend:** Node.js with Express.
- **Database:** PostgreSQL (Relational data is vital for Inventory/Accounting).
- **Caching:** Redis (for live analytics).

### Database Schema (Core Tables)

- **Users:** ID, Name, Role (Admin/Sub-Admin), Permissions.
- **Inventory_RM:** Item_ID, Quantity, Type (Raw/Scrap), Location (Central/Direct).
- **Real_Estate_Assets:** Asset_ID, Parent_ID (for sub-divisions), Type (Plot/Unit), Status.
- **HR_Payroll:** Emp_ID, Attendance_Logs, Salary_Base, DPR_Link.
- **Vendor_Quotes:** Quote_ID, Item_ID, Vendor_Name, Amount, File_URL, Status (Approved/Rejected).

## 6. User Stories & Workflows

### User Story: The Site Supervisor

> "As a Site Supervisor, I want to log the number of laborers and bags of cement used today on my mobile app, so that the Admin can see the construction cost rising in real-time."

### Workflow: Purchasing

1. Purchaser identifies need for 10 tons of steel.
2. Purchaser collects 3 quotes and uploads them to the app.
3. System highlights the lowest price.
4. Admin receives notification -> Approves/Rejects.
5. On approval, entry is automatically pushed to Tally.
