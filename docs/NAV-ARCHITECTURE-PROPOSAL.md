## The Problem

The current 5-world rail (Profile → Inventory → HR → Financials → Admin) is thoughtful but has structural friction:

1. **Inventory sub-branching adds a layer.** You enter Inventory, then pick Raw Material or Real Estate, then navigate. That's 3 clicks to reach a page. The owner thinks "Inventory has two things" — but those two things are one pipeline, not two parallel silos.

2. **The value flow is invisible in the nav.** The core workflow is: buy material → issue to project → project cost rises → unit value increases → sell unit. This crosses the Raw Material / Real Estate sub-branch boundary on every step.

3. **SALES users enter Inventory and see a dead sub-branch.** They can't access Raw Material pages, so half the world is empty space.

4. **Project Controls are split across two worlds.** BOQ, WBS, Measurement Book, Work Orders are in Inventory/Real Estate. Budget Variance, Project Control, Profit Center are in Financials. But they answer the same question: "how is this project doing?"

5. **14 hidden reports in Financials.** The sidebar shows 6 links; the other 14 are on /reports. But the /reports grouping is by abstract question ("Are we making money?"), not by the workflow that produces the data.

6. **The project hub already proves contextual hubs work.** `/projects/[id]` has 7 tabs (Overview, Procurement, Stock, Units, Land, Finance, Equipment) that pull from multiple worlds into one page. But it's missing BOQ, WBS, Work Orders, Measurement Book, DPRs, and Reconciliation — the things that would make it a true project cockpit.

---

## The Proposal: 4 Worlds + Context Hubs

### Principle

> **The rail tells you WHERE you are. The hubs tell you WHAT you're working on.**

The rail is minimal (4 worlds + a gear). The real navigation intelligence lives in **context hubs** — pages that pull from multiple worlds into one focused view, organized around the thing you're working on (a project, a material, a supplier, a unit).

---

### The Rail: 4 Worlds

```
┌──────┐
│  ☀   │  TODAY      — you, your work, what needs you
├──────┤
│  🏗  │  BUILD      — the entire asset lifecycle (land → material → project → unit → sold)
├──────┤
│  👷  │  PEOPLE     — labour, attendance, DPR, payroll
├──────┤
│  💰  │  BOOKS      — money, GL, tax, reports
├──────┤
│  ⚙   │  (settings — always at bottom, not a world)
└──────┘
```

**What changed:**
- **Inventory → Build.** Merges Raw Material + Real Estate into one world. Eliminates the sub-branch layer. The two aren't parallel silos — they're stages of one pipeline.
- **Admin → gear icon.** Settings doesn't need to be a world. It's a gear at the bottom of the rail, always accessible, never in the way.
- **5 worlds → 4 worlds.** Less cognitive load. Every role sees a shorter rail.

**20 links is too many for one panel.** The solution is below: **adaptive sections by role**.

#### Role-Adaptive Section Visibility

The panel doesn't show all 5 sections to every role. It shows only the sections that role can act on:

| Role | Sees sections | Link count |
|------|--------------|------------|
| OWNER/ADMIN | All 5 | 20 (scrollable, sectioned) |
| MANAGER | All 5 | 20 |
| SUPERVISOR | Procure (GRN), Stock, Construct | ~9 |
| SALES | Construct (Projects), Sell | ~6 |
| ACCOUNTANT | Acquire (Suppliers), Procure, Stock, Construct | ~13 |

This is the key insight: **SALES never sees Procure or Stock. SUPERVISOR never sees Sell.** The panel is genuinely smaller for them, not the same panel with hidden links.

## The Smart Part: Context Hubs

The rail gets you to the right world. **Context hubs get you everything about one thing without switching worlds.**

The project hub (`/projects/[id]`) already does this with 7 tabs. The proposal is to **expand it to a full project cockpit** and add two more hubs.

### Hub 1: Project Cockpit (`/projects/[id]`)
*Everything about one project in one page.*

Current tabs: Overview, Procurement, Stock, Units, Land, Finance, Equipment

**Add tabs:**

| Tab | What it shows | Pulled from |
|-----|--------------|-------------|
| Overview | Status, cost, progress, cost/sqft | — |
| Procurement | POs, requisitions for this project | Build/Procure |
| Stock | Issues, transfers, on-hand at site | Build/Stock |
| Construction | BOQ, WBS, Measurement Book, Work Orders | Build/Construct |
| **DPRs** *(new)* | Daily progress reports for this project | People |
| **Costs** *(new)* | Material cost, labour cost, work orders, expenses, land cost | Books + Build |
| **Variance** *(new)* | BOQ vs actual, consumption vs benchmark, EVM metrics | Build/Construct + Books |
| Units | Built units, status, valuation, sales | Build/Sell |
| Land | Parcels, partitions, valuation | Build/Acquire |
| Finance | Project costs, P&L | Books |
| Equipment | Assigned equipment | Build/Stock |

**Why this is smart:** A manager tracking a project currently switches between Build (issues), People (DPRs), and Books (costs) to understand one project. The cockpit puts it all in one page with tabs. The nav worlds are for browsing; the hubs are for working.

### Hub 2: Material Cockpit (`/materials/[id]`)
*Everything about one material in one page.*

| Tab | What it shows |
|-----|--------------|
| Overview | Specs, unit, reorder level, EOQ, current MAC per location |
| Stock | On-hand by location, movements ledger |
| Procurement | Open POs, requisitions, rate contracts, supplier history |
| Consumption | Issues by project, consumption benchmarks, variance |
| Performance | Price trend, supplier comparison, purchaser performance |

**Why this is smart:** A storekeeper asking "do I need to reorder cement?" currently checks Stock, then Requisitions, then Purchase Orders, then Materials. The material cockpit answers the question in one page.

### Hub 3: Supplier Cockpit (`/vendors/[id]`)
*Everything about one supplier in one page.*

| Tab | What it shows |
|-----|--------------|
| Overview | Contact, GST, rating |
| Orders | POs, delivery history, on-time rate |
| Financials | Outstanding, payment history |
| Quotes | Quotes submitted, win rate, price competitiveness |

## The Fast Path: Command Palette (⌘K)

The command palette already exists. The proposal is to make it **context-aware**:

- When you're in a project cockpit, ⌘K shows project-scoped actions first ("Issue material to this project", "Create DPR for this project", "Add project cost")
- When you're in a material cockpit, ⌘K shows material-scoped actions first ("Create requisition", "View stock movements")
- Global search always available below the context actions

This means power users rarely touch the rail — they navigate by search + context.

2. **Your primary world** (Build for site/sales, Books for accountant)
3. **Quick actions** (the 3-4 things this role does most)

## Before / After: Common Workflows

### Workflow: "Issue material to a project and see the cost impact"

**Before (current):**
1. Enter Inventory → Raw Material sub-branch → Stock → Issues tab → create issue
2. Switch to Inventory → Real Estate sub-branch → Projects → find project → Finance tab
3. 2 sub-branch switches, 2 world-panel scrolls

**After (proposed):**
1. Enter Build → Stock → Issues tab → create issue (link to project)
2. OR: Enter Build → Construct → Projects → open project cockpit → Stock tab → issue
3. Stay on project cockpit → Costs tab → see updated cost
4. **1 world, 0 sub-branch switches**

### Workflow: "Review a DPR and check material variance"

**Before:**
1. Enter HR → DPRs → open DPR
2. Run variance analysis → see scrap detected
3. Switch to Inventory → Raw Material → Stock → Scrap tab → see scrap
4. 1 world switch + 1 sub-branch switch

**After:**
1. Enter People → DPRs → open DPR → variance tab (right there)
2. OR: Enter Build → Construct → Projects → project cockpit → DPRs tab → variance
3. **0-1 world switches**

### Workflow: "Close the books this month"

**Before:**
1. Inventory → Raw Material → GRN (check receipts posted)
2. Inventory → Raw Material → Stock → Issues (check issues posted)
3. HR → Payroll (run payroll)
4. Financials → Finance (check expenses)
5. Financials → GL (review trial balance)
6. Financials → GL → Tally sync
7. **2 world switches**

**After:**
1. Build → Procure → GRN
2. Build → Stock → Issues
3. People → Payroll
4. Books → Finance
5. Books → GL → Tally sync
6. **2 world switches** (inherent — money flows from operations to books)

### Workflow: "Sell a unit"

**Before:**
1. Inventory → Real Estate → Built Units → find unit
2. Inventory → Real Estate → Sales → create booking
3. Inventory → Real Estate → Portal Listings → sync/delist
4. **0 world switches, but 3 sub-branch scrolls within Real Estate**

**After:**
1. Build → Sell → Built Units → find unit
2. Build → Sell → Sales → create booking
3. Build → Sell → Portal Listings → sync/delist
4. **0 world switches, 0 sub-branch scrolls — all in one "Sell" section**

## Summary of Changes

| Change | Impact |
|--------|--------|
| Merge Inventory (2 sub-branches) → Build (5 flat sections) | -1 navigation layer, pipeline visible |
| Admin world → Settings gear | -1 world in the rail |
| Role-adaptive section visibility in Build | Genuinely smaller panel for SALES/SUPERVISOR |
| Expand project hub → project cockpit (add DPRs, Costs, Variance, Construction tabs) | Cross-world workflow in one page |
| Add material cockpit + supplier cockpit | Object-centric deep views |
| Regroup /reports by Build section | Report picker mirrors the pipeline |
| Context-aware command palette | Power users navigate by search + context |

---

## What NOT to Change

- **The 5-8 links per panel rule.** Build has 20 links, but role-adaptive section visibility keeps it to 6-13 per role. Sections provide visual grouping.
- **The world color system.** Wayfinding colors stay — Build gets Inventory's color.
- **The badge system.** Live counts on requisitions, POs, approvals stay.
- **The mobile shell architecture.** Role-based shells are correct; just align naming.
- **The hidden report pattern.** Reports stay on /reports, not in the sidebar. Just regrouped.
- **Soft deletes, RBAC, GL posting, stock ledger rules.** This is a nav proposal, not a data architecture change.
